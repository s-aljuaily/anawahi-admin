# منصّة إعلانات «أنا و هي»

صفحة واحدة تنشر إعلانًا يصل **كل من يستعمل التطبيق** — داخل التطبيق وعلى شاشة القفل.

## لماذا بلا خادم وبلا مفتاح سرّي

الحراسة كلّها سياسات `RLS` داخل قاعدة البيانات، لا في هذه الصفحة. فالصفحة تحمل
المفتاح المنشور (anon) وحده — وهو المفتاح نفسه الموجود في التطبيق على جوّال كل
مستخدم. لو فُتحت هذه الصفحة من أي جهاز في العالم فلن تنشر شيئًا: قاعدة البيانات
ترفض الإدراج لمن ليس في جدول `app_admins`.

إخفاء زرّ النشر ليس حماية. رفضُ قاعدة البيانات هو الحماية.

## التشغيل — ثلاث خطوات

### ١) أنشئ الجداول
افتح Supabase ← **SQL Editor** ← New query ← الصق محتوى `supabase/announcements.sql` ← **Run**.

### ٢) عيّن نفسك مشرفًا
افتح المنصّة وسجّل الدخول — **مربوطة بمشروعك مباشرةً، لا إعداد ولا كتابة**. ستقول لك إن حسابك ليس مشرفًا، **وتعرض عليك سطر SQL
جاهزًا بمعرّفك**. انسخه وشغّله في SQL Editor، ثم حدّث الصفحة.

### ٣) افتح المنصّة

**<https://s-aljuaily.github.io/anawahi-admin/>**

مرفوعة على GitHub Pages — تفتحها من أي جهاز وأي مكان، بلا تشغيل شيء على حاسوبك.

**مستودعها:** <https://github.com/s-aljuaily/anawahi-admin> — لتحديثها ادفع
`admin/index.html` إليه.

> **كونها عامّة لا يُضعف الأمان.** من يفتحها بلا حساب مشرف لا يفعل شيئًا: كل
> كتابة تمرّ بسياسات `RLS` فتُرفض. وما فيها من مفاتيح هو المفتاح **المنشور**
> نفسه الموجود في التطبيق على جوّال كل مستخدم.

**وللتشغيل محليًّا** عند التطوير:

```bash
cd admin && npx serve -l 4173 .
```

> **لا تفتحها بـ`file://`** — الدخول عبر Google يحتاج عنوانًا حقيقيًّا،
> و`localStorage` معطَّل في بعض السياقات المحلّية.

### ملاحظة إعداد لازمة
Supabase ← Authentication ← **URL Configuration** ← أضف في **Redirect URLs**:

```
https://s-aljuaily.github.io/anawahi-admin/
```

بدونها يفشل الدخول عبر Google من الرابط المرفوع.

### عن الربط المباشر
عنوان المشروع والمفتاح **المنشور** مثبَّتان داخل الصفحة. وضعهما هناك لا يكشف
شيئًا: هما نفسهما داخل التطبيق على جوّال كل مستخدم ويمكن استخراجهما منه بدقائق،
والمفتاح المنشور لا يمنح صلاحية بذاته — سياسات `RLS` هي التي تقرّر. زرّ
«الإعدادات» بالأعلى لتوجيه المنصّة لمشروع آخر إن لزم.

**لنشرها على الإنترنت** (لتفتحها من أي مكان): ارفع مجلّد `admin` إلى Vercel أو
Netlify أو Cloudflare Pages — مجلّد ثابت بلا بناء. ثم أضف عنوانها في
Supabase ← Authentication ← URL Configuration ← **Redirect URLs**.

## الإشعار الفوري — خطوتان

**Expo لا تقبل الطلب من متصفّح.** لا تُرسل ترويسة `Access-Control-Allow-Origin`،
فيقتل المتصفّح الطلب قبل خروجه. وهذا حدٌّ مقصود يمنع أي صفحة في العالم من قصف
خدمة الإشعارات — لا عيب يُلتفّ عليه. فالمخرج طرفٌ خادمٌ يُرسل:

**١)** فعّل القسم ٣ في `announcements.sql` (قراءة رموز الإشعارات للمشرف).

**٢)** Supabase ← **Edge Functions** ← Deploy a new function ← اسمها `send-push`
← الصق `supabase/send-push-function.ts` ← Deploy.

الدالّة تتحقّق من هويتك **برمزك أنت** ثم تسأل قاعدة البيانات: هل هو مشرف؟ فإن لم
يكن ردّت ٤٠٣. **لا مفتاح سرّي ولا تجاوز لسياسات RLS في أي خطوة.**

### وإن لم تفعل شيئًا من هذا
يصل الإعلان داخل التطبيق، **ويُنبّه كل جهاز نفسه محليًّا** عند فتحه — فيظهر على
شاشة القفل بلا أن تقرأ المنصّة رمز أحد. الفرق أن التنبيه يصل عند فتح التطبيق لا
في اللحظة نفسها. والمنصّة تقول لك أيّ الحالتين أنت فيها قبل النشر.

## الصورة

تُرفع إلى مخزن عامّ اسمه `public-assets` (أنشئه من Supabase ← Storage ← New bucket
← Public). وتظهر داخل **لوحة** الإعلان على الرئيسية.

ظهورها داخل الإشعار نفسه على iOS يحتاج `Notification Service Extension` في نسخة
أصلية جديدة — غير مضافة بعد، فلا تعتمد عليها الآن.

## ما لا تفعله هذه المنصّة

- **لا فئات مستخدمين.** كل مستخدمي التطبيق أزواج متساوون — لا مشترون ولا مزوّدون.
  فالإعلان يصل الجميع.
- **لا رسائل خاصّة.** ما يُنشر هنا يُقرأ على كل جهاز. الرسالة بين الزوجين هي
  «لمسة اليوم» داخل التطبيق.
